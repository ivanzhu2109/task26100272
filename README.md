# synarchive

进程内的客服消息档案同义短语检索库（Go），由上层直接调用，数据驻留内存，
只支持两个操作：`Build` 建立只读档案、`Search` 执行单短语查询。

## 语义

- 上层已完成切词与大小写统一；消息、查询、规则两侧均为非空词元序列，词元按完整字符串比较。
- 同义规则是有方向的词元序列替换（`Rule{From, To}`）。查询可保留全部原词元，
  也可选择任意个互不重叠、与某条规则左侧完全相同的原查询片段替换为右侧；
  替换只作用于原查询，展开结果不再套用规则；规则不隐含反向关系，不改动档案消息。
  规则可重复、可成环、左侧可在查询中重叠，均不改变一次替换语义。
- 某个合法展开与消息中连续词元片段完全一致即命中。
  tf = 该消息中不同命中起点的数量（同一起点被多个展开/多种长度命中只算一次，
  不同起点即使片段重叠也分别计数）；df = 至少命中一次的消息总数。
- 整个查询短语视为一个检索项，BM25 评分：
  `ln(1+(N-df+0.5)/(df+0.5)) * tf*2.2 / (tf + 1.2*(0.25+0.75*dl/avgdl))`。
  N、dl、avgdl 为档案固有统计，不随展开或命中集合改变。
- 结果按得分降序，得分相同按消息编号升序。

## 使用

```go
a := synarchive.Build(
    []synarchive.Message{
        {ID: 1, Tokens: []string{"a", "a", "a"}},
        {ID: 2, Tokens: []string{"a"}},
    },
    []synarchive.Rule{
        {From: []string{"a"}, To: []string{"a", "a"}},
    },
)
hits := a.Search([]string{"a", "a"}) // []Hit{ID, Score, TF}
```
